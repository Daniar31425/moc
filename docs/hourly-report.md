# Почасовой отчёт

## Hour 1

- Время: 0:00–1:00
- Commit hash: архитектурный checkpoint; точный hash — в истории `main` (`git rev-parse HEAD`)
- Что планировали: выбрать один сценарий, зафиксировать стек и API-контракт, создать запускаемые каркасы frontend/backend.
- Что реализовали: структура репозитория, FastAPI mock API, React/Vite экран, документация, переменные окружения и проверки.
- Что работает: ввод темы и параметров, запрос к backend, отображение mock-микроурока; health check.
- Какие тесты прошли: `pytest` — 3/3; `vite build` — успешно; реальный HTTP health и POST генерации — `200 OK`.
- Известные проблемы: OpenAI ещё не подключён; проверка ответа в интерфейсе пока только визуальная.
- Изменения API-контракта: создана и заморожена версия v1.
- Работа Данияра: архитектура, backend-каркас, контракт, общие файлы.
- Работа Каната: frontend-каркас основного сценария.
- Следующая задача Данияра: заменить mock внутренней интеграцией OpenAI Responses API без изменения контракта.
- Следующая задача Каната: добавить интерактивный выбор ответа и состояния правильного/неправильного ответа без новых маршрутов.
- Основной риск: нестабильный интернет или лимит API во время демо.
- Что исключили из MVP: аккаунты, каталог курсов, прогресс, база данных, видео, платежи, роли преподавателей, админка.
- Статус демонстрационного сценария: готов на mock; реальная генерация запланирована на Hour 2.

## Hour 2

- Время: 1:00–2:00
- Commit hash: backend checkpoint; точный hash — в истории ветки `backend` после коммита.
- Что планировали: подключить OpenAI Responses API, завершить серверную логику, ошибки и валидацию.
- Что реализовали: конфигурация из окружения, OpenAI Structured Outputs через Pydantic, серверный таймаут 25 секунд, mock fallback, русская и казахская mock-локализация, единые ошибки.
- Что работает: `GET /api/v1/health`; `POST /api/v1/lessons/generate` в mock-режиме; код реального OpenAI-режима и нормализация ответа.
- Какие тесты прошли: `pytest` — 7/7; реальный HTTP health и POST в mock-режиме — `200 OK`; ровно 3 варианта ответа.
- Известные проблемы: live-вызов OpenAI не выполнен, потому что локальный `OPENAI_API_KEY` не настроен; есть одно предупреждение зависимости Starlette в тестовом клиенте.
- Изменения API-контракта: нет; маршруты, поля и типы сохранены.
- Работа Данияра: backend, OpenAI SDK, валидация, ошибки, тесты и документация.
- Работа Каната: frontend не изменялся; должен проверить отображение `generated_by=openai` и согласованные сообщения ошибок.
- Следующая задача Данияра: live-проверка с ключом, интеграция готовой frontend-ветки и сквозной тест.
- Следующая задача Каната: завершить выбор варианта ответа и проверить loading/success/error против backend.
- Основной риск: отсутствие рабочего ключа, лимита или сети на демонстрации; закрывается `USE_MOCK=true`.
- Что исключили из MVP: хранение уроков, история, повторные попытки OpenAI, стриминг и дополнительные маршруты.
- Статус демонстрационного сценария: стабилен в mock; OpenAI-код готов, live-проверка ожидает ключ.
